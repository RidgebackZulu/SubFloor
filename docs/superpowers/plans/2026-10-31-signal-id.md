# Signal ID Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Point at any signal (hover, right-click or an agent) and SubFloor measures it (family and parameters) and names it from a table of about 30 HF and VHF modes, without decoding it.

**Architecture:** A new pure `SignalID` library target turns a short IQ snapshot into a `SignalMeasurement` (family, bandwidth, baud, shift, tones, PSK order, OFDM spacing and so on), then a `SignalIdentity` (best named match plus alternatives with confidences) from a mode table with frequency hints. The app takes snapshots from the IQ recorder's pre-roll ring, which the DSP thread already writes, and runs the analysis off the main thread with a short cache. The UI adds a hover line and a right-click ID card. The MCP tools gain `get_cursor.signal`, `identify_signal` and `identify_signals`. The decoder's existing auto-detect is switched back on, with a working RTTY rule.

**Tech Stack:** Swift 6, Accelerate/vDSP, DSPCore (NCO, FIR, FIRDecimator, windows, FractionalResampler), SwiftUI/AppKit, Swift Testing. No new package dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-signal-id-design.md`

## Global Constraints

- **Platform:** macOS 15, swift-tools 6.0, no new package dependencies. The new library target is `SignalID`
  (depends on `DSPCore` only), with test target `SignalIDTests`. The `SubFloor` executable depends on
  `SignalID`.
- **Naming threshold:** a mode is named only at confidence ≥ **0.7**. Below that the result is the family and
  its parameters, with the alternatives listed.
- **Reads:** the first pass reads the last **3 s** of IQ. A second pass reads up to **16 s** when the signal
  is under 50 Hz wide, keys slower than 10 WPM, or has a candidate that needs timing (WSPR, FT8/FT4 slots,
  fax lines, time ticks). Both use only samples since the last retune. Less than **1 s** gives
  "Too soon after tuning — try again".
- **Budget:** the first pass takes ≤ **150 ms** per signal in a release build on Apple Silicon, and the second
  pass ≤ 1 s. Neither ever runs on the main thread or the DSP thread.
- **Hover:** a dwell of **0.5 s** triggers an ID. Results are cached for **5 s** per frequency.
  `get_cursor` identifies the mouse only when it rested within **30 s**.
- **SNR:** signal power over noise power within the signal's own occupied bandwidth. The line reads
  "Too weak to identify (SNR n dB)" below the family threshold.
- **Decode confirmation:** only from decoders already running in the decoder panel, decoding the same
  signal within the last 60 s. The confidence then goes to 1 and the card says "confirmed by decode".
- **`identify_signals`:**
  - Inside the current capture it doesn't touch the radio.
  - Wider than one capture, it steps the radio under `withRadio`, dwelling until the ring holds at least 3 s.
  - It refuses with "The owner is recording: scan only within the current view, or ask the owner" while any
    recording is running or Auto is on.
  - Afterwards it restores the VFO, mode, bandwidth and HamItUp, and it stops early if the owner retunes.
- **Accuracy targets (synthetic signals):**
  - At ≥ 10 dB SNR:
    - family right ≥ 95%;
    - symbol rate within 1% (WSPR within 3%);
    - shift within 3%;
    - bandwidth within 10%;
    - named mode right ≥ 90% where the parameters are distinctive.
  - At 3 dB: wrong names at ≥ 0.7 confidence ≤ 2%.
- **Mode table:** exactly the HF and VHF-and-up rows in the spec, with their parameters and hints.

## Review Focus

1. **A retune in the middle of a snapshot.** Samples from two capture centres must never be analysed
   together. Pinned in Task 1, test `snapshotStopsAtTheRetune`.
2. **Pointing at empty noise, or at the edge of a strong signal's splatter.** It says "No signal" or gives the
   strong signal's identity, never a name for the splatter. Pinned in Task 2, test `noiseAndSplatterAreNotNamed`.
3. **Neighbour modes with near-identical parameters (DMR / YSF / P25).** It shows alternatives and the family,
   never a confident wrong single name. Pinned in Task 5, test `tdmaAndContinuousFourFSKAreToldApartOrNotNamed`.
4. **The hover firing while the mouse moves across the waterfall.** No analysis starts until a 0.5 s dwell,
   and a pending one is cancelled when the pointer moves on. Pinned in Task 8, test `hoverWaitsForADwellAndCancels`.
5. **An agent scan while the owner records.** It refuses and leaves the radio untouched. Pinned in Task 9, test
   `scanRefusesWhileTheOwnerRecords`.

  - `enum EnvelopeKind: String, Codable, Sendable { case steady, keyed, voice, bursty, none }`
  - `struct SignalMeasurement: Codable, Sendable, Equatable`, with fields:
    - `offsetHz` (centre relative to the capture centre)
    - `occupiedBandwidthHz` (−20 dB)
    - `bandwidth6dBHz`
    - `snrDb`
    - `envelope: EnvelopeKind`
    - `family: SignalFamily`
    - `familyConfidence: Float`
    - `symbolRate: Double?`
    - `fskShiftHz: Double?`
    - `toneCount: Int?`
    - `toneSpacingHz: Double?`
    - `pskOrder: Int?`
    - `ofdmSpacingHz: Double?`
    - `fmDeviationHz: Double?`
    - `cwWPM: Double?`
    - `burstPeriodSeconds: Double?`
    - `burstDuty: Double?`
    - `subcarriersHz: [Double]`
    - `seconds` (length analysed)
    - `notes: [String]`
  - **Synthesis:** `enum SignalSynth { static func make(_ spec: SynthSpec, sampleRate: Double, seconds: Double, snrDb: Double, offsetHz: Double = 0, seed: UInt64) -> [Float] /* interleaved IQ */ }`.
    - `SynthSpec` covers every family and named mode in the spec: AM voice, USB/LSB voice, NFM/WFM, CW at
      a WPM, n-FSK (rate, shift or spacing, tones, GFSK on/off), BPSK/QPSK/8PSK (rate, RRC roll-off), MFSK,
      OFDM (carrier count and spacing, with a cyclic prefix), and TDMA bursts (period and duty).
    - Noise is complex Gaussian, scaled so the SNR within the signal's occupied bandwidth equals `snrDb`.
      Voice is shaped noise with a syllabic envelope.
  - **Channel:** `struct Channel { static func extract(_ iq: [Float], sampleRate: Double, offsetHz: Double, bandwidthHz: Double) -> (samples: [DSPComplex], rate: Double) }`.
    It mixes to 0 Hz, low-passes, and decimates to about 4× the bandwidth (at least 8 kHz).
  - **Extent:** `enum Extent { static func find(spectrumDb: [Float], binHz: Double, nearBin: Int, searchBins: Int) -> (lowerBin: Int, upperBin: Int, peakBin: Int, snrDb: Double)? }`.
    - It returns nil when nothing within `searchBins` stands 6 dB above the local noise (the median of
      ±10× the signal width).
    - It grows from the peak until the level falls to the local noise plus 3 dB.

### Task 5: Mode table, matcher, slow second pass and the accuracy matrix

**Files:**
- Create in `Sources/SignalID/`:

    frequency hints as display-Hz ranges.
  - `Identify.swift`
- Create: `Tests/SignalIDTests/IdentifyTests.swift` and `Tests/SignalIDTests/AccuracyMatrixTests.swift`

**Interfaces:**
- Consumes: `SignalMeasurement` (Tasks 3–4).
- Produces:
  - `struct ModeMatch: Codable, Sendable, Equatable { var name: String; var confidence: Float; var evidence: [String] }`
  - `struct SignalIdentity: Codable, Sendable, Equatable { var measurement: SignalMeasurement; var best: ModeMatch? /* nil below 0.7 */; var alternatives: [ModeMatch] /* up to 3, ≥ 0.3 */; var needsLongerRead: Bool; var confirmedByDecode: Bool; var note: String? }`
    - `label: String` is the one-line text, for example `RTTY · 45.45 Bd · 170 Hz shift · 91%` or
      `2-FSK · 50 Bd · 850 Hz shift`.
    - `summary: [String: String]` holds the parameters for the card.
  - `enum SignalIdentifier { static func identify(_ m: SignalMeasurement, rfHz: Double) -> SignalIdentity; static func identify(iq: [Float], sampleRate: Double, captureCenterHz: Double, atHz: Double, bandwidthHz: Double?, spectrumDb: [Float]?, longer: (() -> (iq: [Float], seconds: Double)?)?) -> SignalIdentity }`
    - The second form runs extent, measure and identify.
    - It sets `needsLongerRead` when the spec's slow-signal rules apply, and runs `longer` if one is given.
  - `enum AnalyticAudio { static func iq(fromSSBAudio audio: [Float], sampleRate: Double) -> (iq: [Float], rate: Double) }`
    is the Hilbert-transform entry point for audio fixtures.
  - **Confidence:** each matching parameter or feature adds, each mismatch subtracts, and band hints adjust
    by up to ±0.15. A hint can't push a match to 0.7 when its parameters alone score below 0.55.
